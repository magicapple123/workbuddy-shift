# WorkBuddy Shift 0.4.0

发布日期：2026-11-26

新增一个功能，顺带修掉两个会直接影响导入与切号的判定问题；账号、备份、关联与会话数据格式都没有变化，0.3.x 可以直接升级。

## 新功能：跨组安全批量同步（issue #231）

以前一个会话组里有多个落后副本时，要在组详情里逐个点同步；组多了只能一组一组打开。0.4.0 起，关联会话列表页会显示「**同步 N 个待同步组**」：

- 一次把当前客户端下所有**能安全快进**的副本同步完，不用逐组打开；
- 只做快进：出现分歧、无法确认来源、没有落后副本的组会**整组跳过**，结果里说明原因，绝不替你选「保留哪一份」；
- VS Code / JetBrains 插件端全程**只关闭一次、结束后重新打开**，不会一组关一次；
- 执行前会逐组重新复核一次，列表上的状态过期（例如刚在客户端里改过）就跳过该副本，不算成功。

跨组入口只在有「待同步」组时出现；想先看某个组的分歧详情，仍然点开该组手动处理。

## 新功能：第三方号池 JSON 导入兼容（issue #232）

从 BuddyRelay 等工具导出的号池 JSON 现在可以直接导入：

- 凭据字段兼容 camelCase：`accessToken` / `refreshToken`，以及简写 `token`；本工具自己的 `access_token` 仍然优先，不会被别名覆盖；
- 支持 `{ "accounts": [...] }` 包装对象，不再要求顶层必须是数组；
- 其它字段（`domain`、`expiresAt`、`authRaw` 等）原样保留，不裁剪、不改名。

同时把两种「看着像 JSON、其实导不进去」的情况说清楚了：

- **脱敏分享**导出的文件本来就没有凭据，任何工具都导不进去，需要在对方工具里选「完整凭证」重新导出；
- **加密池密文**（`enc:v1:` 开头）本机解不开，预览会标成「加密池密文」并拒绝入库，不会留下一条「有 token 但用不了」的账号；整份文件都被跳过时，导入结果会弹警告而不是「导入成功」。

## 修正：国际版域名判定

`www.codebuddy.ai` 以及 apex `workbuddy.ai` / `codebuddy.ai` 以前会被判成国内版，导入国际号池后切号会打到错误的客户端。现在按标签边界识别 `workbuddy.ai` / `codebuddy.ai` 两个域及其子域；相似域名（如 `www.codebuddy.ai.evil.com`、`notcodebuddy.ai`）仍不会被误判。显式写了 `variant` 的账号仍以显式字段为准。

## 升级后要做什么

不需要迁移，也不需要重新导入账号：

- 已有关联组、账号、备份照常使用；
- 之前导入失败或显示「缺少 token」的 BuddyRelay 号池，重新用「完整凭证」导出一次，再走「导入备份」即可；
- 跨组批量同步是新入口，第一次用建议先在一个组上确认文案与结果符合预期。

## 已知限制

- 跨组批量同步只处理「能安全快进」的副本；分歧组仍需打开该组手动选择保留哪一份。
- CodeBuddy IDE 运行时会用内存态覆盖磁盘，批量同步前需要先完全退出（不会替你关闭）。
- 一次批量超过 199 个目标时，最早的目标预览凭据可能被工具自己的凭据上限挤掉，表现为中途提示「预览过期」；正常使用不会达到这个量级。
