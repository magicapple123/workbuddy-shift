# WorkBuddy Shift 0.3.3

发布日期：2026-11-24

只修缺陷，不加功能。数据、账号、备份与关联基线都没有变，0.3.0–0.3.2 可以直接升级。

## 修复了什么

**1. 目标账号里「活跃时间」不再冻在复制那一刻**

问题表现：目标账号的会话列表或项目卡片上，某条会话的时间停在很早以前；但点进去，对话内容其实已经是最新的。源账号看起来正常。

原因是客户端列表读的是会话记录里的「活跃时间」这一列，而本工具以前在复制时把它从源账号原样搬过来、之后每次同步都只更新正文和「更新时间」，**从来不更新它**。于是副本的时间冻结在第一次复制那一刻，正文却一直在同步。

0.3.3 起：

- 复制时取「源账号的值」与「正文最后一条消息的时间」中较新的一个，并且不会超过当下（源机时钟超前时不会跑到未来）；
- 同步时只前进不回退，同样不会写进未来时间；写入后会在同一个事务里回读校验；
- 只做「归档同步」（不写正文）时不会动这个字段；
- 老版本客户端没有这一列时整列不写，不报错。

**2. 项目归属失败不再静默**

如果目标账号里既找不到对应项目、又没法新建分组，副本会被写成「无项目」：会话还能从「最近」或搜索打开，但在项目里怎么都找不到，而复制报告里以前什么都不说。现在会在复制结果的 `spaceNote` 里明确写「未能定位或新建项目分组，副本未归入任何项目」。源会话本来就没有项目的正常情况不会误报。

> 说明：这条提示目前只出现在复制结果的 JSON/CLI 里，界面上的提示会另开一版补。

## 升级后要做什么

**受影响的会话需要再同步一次**，活跃时间才会刷新——修复只作用于之后的复制与同步，不会自动回溯修正存量数据。

- 打开会话组页面 →「同步」，选「以较新的一侧为准」即可；不需要解除关联、不需要删副本。
- 如果某条会话本来就没有建立关联（历史上是直接复制过去的），可以先「解除关联」→「新增关联会话」，勾选「复制内容」和「建立关联」。

## 下载哪个？

| 你的系统 | 下载这个 | 说明 |
| --- | --- | --- |
| Windows 10 / 11（x64） | `workbuddy-shift_0.3.3_x64-setup.exe` | 安装包未做代码签名，SmartScreen 会拦一次：点「更多信息」→「仍要运行」 |
| macOS（Apple 芯片，M 系列） | `workbuddy-shift_0.3.3_aarch64.dmg` | 首次打开若提示「无法验证开发者」，Control + 点击应用 →「打开」 |
| macOS（Intel） | `workbuddy-shift_0.3.3_x86_64.dmg` | 同上 |
| Linux（通用） | `workbuddy-shift-linux-x86_64.AppImage` | 下载后 `chmod +x` 再运行 |
| Debian / Ubuntu | `workbuddy-shift-linux-x86_64.deb` | `sudo dpkg -i` 安装 |
| 不想装桌面版 | `npm i -g workbuddy-shift` | 需要 Node.js 20.19+ |
| 服务器 / NAS | `docker pull ghcr.io/magicapple123/workbuddy-shift:0.3.3` | 默认只绑 `127.0.0.1`，局域网访问要显式放开 |

**分不清 Mac 是哪种芯片**：左上角 Apple 菜单 →「关于本机」，看「芯片」一行——Apple M 系列选 `aarch64`，Intel 选 `x86_64`。

## 其余文件是什么？

| 文件 | 用途 |
| --- | --- |
| `*.sig` | 自动更新的签名文件，不要手动下载 |
| `latest*.json` | 客户端检查更新用的清单，不要手动下载 |
| `workbuddy-shift-macos-*.app.tar.gz` | macOS 自动更新包，供应用内更新器使用 |

## 升级说明

- **桌面版**：应用内「检查更新」直升，或下载对应安装包覆盖安装；配置与账号库都会保留。
- **npm 版**：`npm i -g workbuddy-shift`。
- **Docker**：`docker pull ghcr.io/magicapple123/workbuddy-shift:0.3.3`。
