# WorkBuddy Shift 0.5.0

发布日期：2026-11-27

这一版加两个排障相关的能力（诊断包、失败动作），顺手把统计口径与设置页的结构收敛掉。账号、备份、关联与会话数据格式都没有变化，0.4.x 可以直接升级。

## 新功能：诊断包

反馈问题最费时间的不是修，是「问清现场」——版本多少、什么宿主、哪个客户端没装、日志最后一条说什么。0.5.0 在「设置 → 诊断包」给了一个一次导出的入口：

- 内容是版本、OS/架构、宿主形态、界面语言、最近 20 条错误日志、设置项**键名与值类型**、账号数量区间、各客户端是否安装、工具数据目录状态、限额监听 hook 状态；
- **自动脱敏**：路径、URL、邮箱、令牌、UUID、长数字、用户名七类占位符，URL 只保留 `scheme://host` 便于判断是哪家网关；`Authorization: Bearer …` 里的短令牌也会被认出来抹掉；
- 桌面端存成 `workbuddy-shift-diagnostics-<时间>.txt`，网页版可复制或由浏览器下载；
- 结构性保证：装配模块**不引用**账号、登录态、OAuth、会话任何一层，报告里不可能出现账号库字段——这是编译期事实，不是约定。

## 新功能：失败时告诉你下一步做什么

以前报错只有一句话，用户不知道是该重新登录、查代理，还是把日志发过来。0.5.0 起，网络类失败会带上结构化档位，界面按档位给动作：

| 档位 | 界面动作 |
|---|---|
| 登录过期 | 重新登录（OAuth 弹窗里是重新发起扫码） |
| 网关返回网页（代理/网关劫持） | 跳到「设置 → 自动更新」检查代理地址 |
| 响应畸形 | 复制一段脱敏诊断摘要 |

三条约束：没有档位就整块不渲染；动作没有落点（例如当前环境没有对应设置节）就不放按钮；不新造流程，三档全部复用既有能力。切号与 OAuth 是本地操作，不产生这三档，界面上不会出现空动作行。

## 改进

- **统计范围收敛**：积分页与 Token 页此前各有外观相近的两套范围控件、默认值还不一致。现在只有页面顶部一处（`统计范围`），两页共用同一份区间定义与逐日过滤口径；今天 / 7 天 / 30 天共用同一个取数窗口，切换不重复请求；跨标签同步失败会落到页面错误条并提供「重试」，不再只弹一次 toast。
- **设置页结构**：按通用 / 账号与同步 / 自动化 / 桌面与维护四组收纳，宽屏左侧目录可跳转并支持 `#settings-xxx` 深链，顶部搜索按节标题、行标题与同义词过滤；自动签到、自动轮换、限额监听支持「恢复默认」，默认值由后端下发，前端不再硬编码。
- **设置包导入导出**：签到、旅行、轮换、限额四份配置可导出一个 JSON，导入在 core 做白名单校验（未知键、半截对象、类型不符整体拒绝且零写入），桌面与网页版共用同一实现。
- **会话列表内存**：列表装配不再缓存正文全文（500+ 份 MB 级正文实测 3.4GB），只按 `path + len + mtime` 缓存摘要、预览与逐行指纹；复制前先比对规范化内容，同内容不再重复搬。
- **账号页**：导出 / 导入 / 加密导出 / 加密导入收进同一个入口；积分条「正常可用」段改用主题数据蓝，与「全部积分包」弹窗保持同一套三色口径。

## 修复

- **切号同步只报「同步失败」不说原因**（issue #3）：判定为 unknown 时的提示现在会带上真实原因（哪一侧、坏在第几行、哪一步没过）；预览与执行之间内容被改写时，也会说明当前哪一侧不可验证，而不是只说「内容已变化」。判定、写入与报告结构一字未改，只补文案。
- **保活不再抢刷当前账号**：刷新前按官方认证文件的新鲜度三选一（回填 / 跳过 / 照旧刷新），避免用账号库里的旧 refresh token 把客户端刚续期的令牌轮换掉，表现为「客户端突然掉登录」。
- **冗余副本判定**：口径从「组内成员数」改为「同组 + 同 uid + 同 variant 的存活副本数」，跨账号副本不再被误标成冗余、也不会被一键清理删掉；「一键清理会删几条」由服务端下发，与列表标记同一口径。
- **积分明细取数**：点选范围、首屏恢复非 30 天窗口、跨标签同步三条路径收敛为一个入口，慢请求不会覆盖新窗口的数字。

## 排障工具

新增只读脚本 `scripts/diagnostics/diagnose-sync-failure.py`：一条命令打印每个关联组的双方 DB 行、正文条数、末行健康度（半截 / 粘连 / NUL / 空行）、同名正文副本、末条 assistant 是否带模型报错、未完成操作日志的 `phase` 与 `lastError`，并给一份标注为「近似」的判定。不写盘、不打印正文，支持 `--home` 与 `--json`。

```bash
python scripts/diagnostics/diagnose-sync-failure.py            # 全部关联组
python scripts/diagnostics/diagnose-sync-failure.py 长任务      # 按标题筛选
```

## 升级后要做什么

不需要迁移，也不需要重新导入账号：

- 已有关联组、账号、备份照常使用；
- 下次反馈前建议先导一次「诊断包」，附在 issue 里能省掉大部分往返；
- 之前撞上「同步失败但看不出原因」的会话，升级后再同步一次即可；若仍失败，把提示原文与诊断脚本输出一起发过来。

## 已知限制

- VS Code CodeBuddy 插件那条会话同步入口本轮**没有**同步这次的文案改动（判定输入与桌面端不同构），它仍可能只显示「检查结果已失效」；桌面端不受影响。
- 诊断脚本在「读不到关联记录」时以 `exit 1` 退出（表示没有产出诊断，不是脚本崩溃）；WAL 模式下只读连接会更新 `-shm`，`db` 与 `-wal` 不会被改。
- 跨组批量同步只处理「能安全快进」的副本；分歧组仍需打开该组手动选择保留哪一份。
