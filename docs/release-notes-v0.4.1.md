# WorkBuddy Shift 0.4.1

发布日期：2026-11-26

只修一个缺陷，不加功能。账号、备份、关联与会话数据格式都没有变化，0.4.0 可以直接升级。

## 修复了什么

**跨组批量同步：目标较多时中途报「预览已过期」（issue #19）**

问题表现：一次勾选很多待同步组执行批量同步，同步到一部分后提示预览凭据过期并停止，剩下的组没有执行。

原因不在同步本身，而在预览凭据的保存策略：每次保存预览凭据都会先按「只保留最近 200 条」清理历史凭据。跨组批量同步会先为**所有**目标生成预览、保存凭据，再逐条执行；当目标超过 199 个时，保存第 200 条就会把同一批的第 1 条删掉，执行到它时自然报「预览已过期」。

0.4.1 起：

- 保存预览凭据不再逐条裁剪，只有目录条目达到 **2000 条**高水位时才清理到最近 200 条；
- 安全余量与历史凭据数相关：批量开始时目录里有 L 条历史凭据，单批目标数不超过 `2001 − L` 时不会被自己的清理挤掉（L ≥ 1800 或单批 ≤ 200 时恒安全）。常见情况 L 约为 200，即单批 1800 个目标以内安全；目录为空时可到 2000；
- 目录增长仍是有界的：峰值不超过 2000 条，达到后清理回 200 条；
- 既有单条预览、配对同步的行为不变。

## 升级后要做什么

不需要迁移。之前批量同步中途停下的，升级后重新执行一次即可，已经同步成功的副本不会重复写入内容。

## 已知限制

- 跨组批量只处理「能安全快进」的副本；分歧组仍需打开该组手动选择保留哪一份。
- CodeBuddy IDE 运行时会用内存态覆盖磁盘，批量同步前需要先完全退出（不会替你关闭）。
