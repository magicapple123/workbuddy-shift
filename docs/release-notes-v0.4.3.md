# WorkBuddy Shift 0.4.3

发布日期：2026-11-26

只修一个缺陷，不加功能。账号、备份、关联与会话数据格式都没有变化，0.4.2 可以直接升级。

## 修复了什么

**WorkBuddy / CodeBuddy IDE：0.4.2 把 hook 超时改得更频繁了（issue #20）**

0.4.2 做了两件事：把 hook 改成「先回复宿主、事件落盘后由后台读取」，并把 hook 的等待上限从 3 秒收紧到 1 秒。第一件事是对的，第二件事是错的：

- 0.4.2 只是去掉了 hook 里等待后台回应的那一步，但每次 hook 仍然要**启动一个约 5MB 的程序**再把事件写到磁盘。
- 在有杀毒软件实时扫描、机械硬盘或冷缓存的机器上，光这一步启动就要 1–2 秒（用户实测中位数 1.88–2.19 秒）。
- 把上限压到 1 秒之后，几乎每一次 hook 都会超时，报错也从 `Hook timed out after 3000ms` 变成了 `Hook timed out after 1000ms`，操作被拦得更频繁。

0.4.3 起：

- hook 不再启动那个大程序，改成注册一个安装时生成的**几行脚本**：读入事件 → 写进自己的临时文件 → 原子改名发布到收件箱 → 输出 `{}`。后台照常增量读取，事件不丢。
- 一事件一文件 + 原子改名，并发触发时不会互相写坏（0.4.2 的共用文件方案在极端情况下会丢事件）。
- 等待上限恢复为 **3 秒**，实测脚本耗时约 40–90 毫秒，余量充足。
- 安装时自动把 0.4.2 注册的命令和更早的旧品牌命令换成新脚本，不会双份触发。
- 卸载时清理注册项并删除脚本；积分签到的 hook、第三方 hook、备份与队列文件一律不动。

## 升级后要做什么

不需要手动改配置。升级后首次启动会自动把旧的注册项换成脚本。

如果你现在正被拦，升级后**完全退出 WorkBuddy 再重开**一次即可。

## 已知限制

- 收件箱依赖本地磁盘写入。磁盘满或用户目录不可写时，该次观察事件会静默丢弃（这是「绝不因为本地磁盘问题反过来拦住你的操作」的有意取舍）。
- 直接删除程序目录（不走卸载流程）的用户，可手动运行 `companion-runtime-v1.exe uninstall-hooks --home <用户目录>` 清理注册项。
