# WorkBuddy Shift 0.4.2

发布日期：2026-11-26

只修一个缺陷，不加功能。账号、备份、关联与会话数据格式都没有变化，0.4.1 可以直接升级。

## 修复了什么

**WorkBuddy / CodeBuddy IDE：hook 超时拦截操作（issue #20）**

问题表现：在 WorkBuddy 里发送消息或调用工具时，偶发报错 `Hook timed out after 3000ms`，操作被拦截；有时把悬浮窗软件关掉、甚至卸载之后仍然报这个错。

原因有两层：

1. 悬浮窗（WorkBuddy Shift Companion）在 WorkBuddy / CodeBuddy IDE 注册了会话观察 hook。旧实现虽然先给宿主回了一个空结果，但进程仍要同步等一次内部通信（最长 3 秒）才退出，而宿主给 hook 的总预算恰好也是 3 秒——bash 启动、程序冷启动、通信排队都算在里面。宿主繁忙时就会撞满预算，把 hook 判成超时并拦截你的操作。
2. 升级前的旧品牌（Agent Studio）注册项没有被清掉，同一个事件被新旧两个程序各触发一次，进一步放大耗时；而且无论关闭软件还是卸载，注册在 WorkBuddy 配置文件里的 hook 都不会被移除，于是「程序都没开了还在拦」。

0.4.2 起：

- WorkBuddy / CodeBuddy IDE 的 hook 改为「即发即走」：立刻回复宿主，把事件写入本地队列后退出，由常驻后台读取处理。queued 的事件即使当时后台没在运行也会保留，启动后自动补读，不会丢；
- 注册钩子的等待上限从 3 秒降到 1 秒作为兜底，不再占用宿主的完整预算；
- 安装时自动识别并移除旧品牌、旧版本的重复注册项，消除双触发；
- 新增卸载清理：卸载程序会移除本工具注册的全部 hook，并写入「不再自动接入」标记，防止残留后台重新装回；
- 积分签到用的 hook、第三方 hook 和备份文件都不受影响，清理逻辑严格只匹配本工具的注册项。

Codex 的 hook 行为不变（仍需等待确认），不受本次改动影响。

## 升级后要做什么

升级后无需手动清配置：程序启动时会自动摘掉旧品牌与旧版本的重复注册项。

如果你现在正被这个问题卡住，升级后仍想立即恢复，可以完全退出 WorkBuddy 再重开；若之前手动关闭过悬浮窗，重新打开一次让它完成清理即可。

## 已知限制

- 首次启动时会自动清理旧的重复注册项，清理前的一两次 hook 可能仍会慢一次，之后恢复正常。
- 卸载清理依赖卸载程序调用；如果你是直接删除程序目录而非走卸载流程，可手动运行 `companion-runtime-v1.exe uninstall-hooks --home <用户目录>` 清理注册项。
